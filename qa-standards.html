Best Practice Code

A few principles I hold every automation suite to, with a quick before/after so the reasoning is concrete rather than abstract.

Locator Strategy

Structural selectors break the moment a class name or DOM depth changes. Role and test-id locators describe intent instead of markup, so they survive redesigns.

Avoid · Playwright TypeScript 
// Breaks the moment a class name or DOM depth changes
await page.locator('div.container > ul > li:nth-child(3) > button.btn-primary').click();
Prefer · Playwright TypeScript 
// Survives most markup and styling changes, and reads like a spec
await page.getByTestId('checkout-submit').click();

// When there's no test-id, an accessible role query works just as well
await page.getByRole('button', { name: 'Submit order' }).click();

No Hard Sleeps

A fixed waitForTimeout is either too short under load or wastes time on every run. Assertions that auto-retry wait exactly as long as needed and no longer.

Avoid · Playwright TypeScript 
await page.click('#save-button');
await page.waitForTimeout(3000); // guessing how long the save takes
expect(await page.locator('.toast-success').isVisible()).toBe(true);
Prefer · Playwright TypeScript 
await page.click('#save-button');
await expect(page.locator('.toast-success')).toBeVisible(); // retries until it appears or times out

Reusable Soft Assertions

A hard assertion stops a test at the first failure, hiding every other broken expectation behind it. Collecting failures and verifying once at the end surfaces everything wrong with a page in a single run.

C# · NUnit 
public sealed class SoftAssertions
{
    private readonly List<Exception> _failures = new();

    public void Check(Action assertion, string label)
    {
        try
        {
            assertion();
        }
        catch (Exception ex)
        {
            _failures.Add(new Exception($"{label}: {ex.Message}"));
        }
    }

    public void Verify()
    {
        if (_failures.Count == 0) return;
        var messages = string.Join("\n", _failures.Select(f => f.Message));
        throw new AssertionException($"{_failures.Count} soft assertion(s) failed:\n{messages}");
    }
}

Playwright + NUnit — Given/When/Then Smoke Test

Category tags keep the smoke suite runnable independently from full regression.

C# · NUnit 
[Test]
[Category("smoke")]
[Category("regression")]
public async Task Test_Login_ValidCredentials_RedirectsToDashboard()
{
    // Given I am on the login page
    await Page.GotoAsync(Config.BaseUrl + "/login");

    // When I submit valid credentials
    await Page.FillAsync("#email", Config.TestUser.Email);
    await Page.FillAsync("#password", Config.TestUser.Password);
    await Page.ClickAsync("#login-submit");

    // Then I land on the dashboard
    await Expect(Page).ToHaveURLAsync(new Regex(".*/dashboard"));
    await Expect(Page.Locator("h1")).ToContainTextAsync("Welcome back");
}

Cypress — Test Structure & Custom Commands

Shared setup lives in a custom command, not repeated in every test, so each test body is just the behavior actually under test.

JavaScript · Cypress 
describe('Checkout flow', () => {
  beforeEach(() => {
    cy.login(Cypress.env('testUser')); // custom command, keeps setup out of each test
    cy.visit('/cart');
  });

  it('lets a signed-in user complete checkout with a saved card', () => {
    cy.get('[data-cy=checkout-button]').click();
    cy.get('[data-cy=saved-card-0]').click();
    cy.get('[data-cy=place-order]').click();

    cy.get('[data-cy=order-confirmation]').should('be.visible');
    cy.get('[data-cy=order-number]').invoke('text').should('match', /^ORD-\d+$/);
  });
});
